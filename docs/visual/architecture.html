The whole thing, once

Six packages. One rule about what may see what, and one line separating the logic this repo actually implements from the infrastructure it stands in for.

Rule one: the client never sees ADK

apps/web and packages/protocol contain no reference to @google/adk. The UI, the reducer and every Playwright assertion are written against FeedEvent — a plain zod union.

ADK is used across the server, the agents package and the providers package. It is the agent runtime, not a detail to be hidden. The invariant worth stating is narrower and actually true: it never reaches the client, and the translation from ADK events to wire events happens in exactly one file.

PackageImports @google/adkWhy it matters
apps/webnothe reducer is testable with array literals
packages/protocolnothe wire contract outlives the framework
apps/serveryes — runner + adapterone file does the translation
packages/agentsyes — it is the runtimeagents, tools, models
packages/providersyes — BaseSessionServiceADK's own interface is the port

The payoff is concrete. Because the reducer cannot see an agent framework, every ordering hazard is an array literal in a test rather than a browser and a stopwatch.

Rule two: substrate sits behind a port

Anything this app does not implement itself is reached through an interface, with an emulated adapter by default and a real one behind a flag. That turns the emulation from an assumption buried in a constructor into a named, observable choice.

The matrix, at runtime

GET /api/health serves this, so the boundary can be checked rather than trusted — and cannot drift away from a document:

capability  mode            emulated  switchable  provider
model       scripted        true      true        Gemini, Vertex AI, any ADK BaseLlm
sessions    memory          true      true        Postgres via ADK DatabaseSessionService
knowledge   keyword         true      true        Vector search: pgvector, Vertex AI Search
identity    trusted-header  true      true        OIDC / JWT
eventLog    memory          true      false       Redis Streams, Kafka, NATS JetStream
fanout      inprocess       true      false       Redis pub/sub, NATS
switchable: false is not a typo

eventLog and fanout have no port yet — they are still hard-wired inside SessionHub, which owns buffering, offset assignment, replay and delivery in one class. Splitting it is surgery on the code three recovery bugs already lived in, so it lands on its own with the recovery test project as the guard.

They are listed anyway. A catalogue that quietly omits what it has not done reads as complete, which is worse than admitting the gap.

What survives a change of substrate

The useful question about any of this is: if I swapped that for the real thing, would the code around it change? Where the answer is no, the mechanism is sound and the emulation is genuinely just a stand-in.

Ours, and unaffected by any provider

The wire protocol and its two counters. The four gates and the drain. The status machine and its terminal guarantee. The per-author message map that keeps parallel agents apart. The resync recovery flow. The agent graph. The eval harness. Swap every provider below the line and none of this changes.

Emulated, with a seam

Sessions, knowledge retrieval, identity. The interface exists, the emulated adapter is the default, and the real adapter is a config flag away. Nothing calling them knows which is answering.

Emulated, no seam yet

The event log and cross-instance fan-out. And one thing that is not emulated at all: there is no message store. The replay buffer is the only place agent messages exist, which is why a rolled-out transcript is unrecoverable and why a thread can come back saying its messages are gone. That is one architectural decision, not three loose ends.

Answers

1. Touch packages/agents, packages/providers (the session port is ADK's own interface) and adk-adapter.ts. Leave apps/web, packages/protocol, the reducer and every browser test alone. 2. At startup, from loadProviderConfig, naming the variable — not on the first request that happens to touch retrieval. 3. So the providers package never imports Express. A port that knows its callers is a shortcut with an interface drawn around it; an Express Request satisfies the hand-written shape structurally anyway. 4. The argument is that each port has a real second implementation in view and a contract suite both must pass. It stops being true the moment a port is added for symmetry rather than for a specific second implementation — that is architecture cosplay, and it is worse than an honest hard-wiring.
