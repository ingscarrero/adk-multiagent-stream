A Model That Never Changes Its Mind

The deterministic BaseLlm that makes streaming tests possible — and the three ADK behaviours it had to learn the hard way.

packages/agents/src/scripted-llm.ts

Why the model is fake

A streaming UI is mostly timing, and timing tests against a real LLM are flaky by construction: token counts vary, latency varies, the model may or may not call a tool. Every test in this repo — unit, integration, Playwright, and the agent evals — runs against this class instead. The result is a suite that needs no API key, no network, and produces byte-identical output on every run.

That one decision is what makes assertions like "the concatenated deltas equal the final text" or "the second tool call is checkShippingStatus" reasonable rather than hopeful. The real Gemini path stays wired up and is exercised by hand; it is simply never on the critical path of CI.

The fidelity that matters

ScriptedLlm mirrors GoogleLlm's streaming shape exactly — N partial responses carrying only the new chunk, then one final non-partial response carrying the whole text. Without that fidelity the adapter would be written against a fake that behaves differently from the real thing, and the tests would prove nothing about production.

Stateless by construction

One instance is shared across every concurrent thread, so it cannot hold a cursor. The turn index is recovered from the request itself.

Three ADK behaviours this class had to learn the hard way

Each was a silent failure, not an error. Each is now pinned by a regression test named after the symptom.

01Transfer rewrites the conversationwrong branch

When control transfers, the receiving agent does not get the raw event log. ADK rewrites the previous agent's tool calls and results into synthetic user messages prefixed "For context:".

Symptom: reading "the latest user message" picked up "For context: ... Transfer queued", so every agent downstream of a transfer matched its default branch and answered the wrong question — fluently, and with no error anywhere.

Fix: latestUserText skips any user content whose first part starts with that prefix.

02The inherited transfer response counted as a turnskipped a step

That same rewritten history includes the transfer's own function response. Counting it advanced the specialist to turn 1 before it had done anything, silently skipping its first tool call.

Fix: completedToolRounds counts only responses for tools the selected branch can actually call.

03Parallel agents minted identical call idsmerged in the UI

Two agents inside a ParallelAgent reach the same script position at the same moment. With ids like call-0-0-searchKnowledgeBase, both emitted the same id, and anything correlating results to calls by id merged two distinct tool calls into one.

Fix: the model name is part of the id, not decoration — callIdPrefix is derived from this.model.

One more, for the record

transfer_to_agent takes agentName in adk-js and agent_name in adk-python. The wrong spelling is a silent no-op rather than an error: the call succeeds, the transfer never happens, and the router answers as itself.

The streaming shape

The abort signal is checked on both sides of each chunk delay, so cancelling mid-stream stops promptly rather than finishing the sentence.

Branches and scripts

A script is an ordered list of branches. The first whose match tests true against the prompt wins, and 'default' always matches — so it goes last.

{ match: /\b(track|shipping|where)\b/i, turns: [
    { kind: 'toolCall', calls: [{ name: 'lookupOrder', args: { orderId: 'A-1001' } }] },
    { kind: 'toolCall', calls: [{ name: 'checkShippingStatus', args: { orderId: 'A-1001' } }] },
    { kind: 'text', text: 'Order A-1001 has shipped...' },
] }

Four turn kinds: text, toolCall, transfer, and error — the last so that error handling has something real to handle. Running off the end of a script emits a loud diagnostic rather than empty text, because silence is the failure mode you cannot debug.

These scripts are the eval fixture

The expectations in packages/eval/evalsets are written against them. Change a script and the eval tells you — which is the point: a behavioural change to an agent should not be able to land quietly.

Trace these yourself

  1. A turn requests three tool calls at once. By how much does the script advance when their responses come back?
  2. A specialist receives control by transfer. Its request contains one transfer_to_agent response and no others. What turn index does it compute, and why does that matter?
  3. Why does the final streamed response carry the whole text rather than the last chunk?
  4. Two ParallelAgent children run the same branch simultaneously. What makes their tool calls distinguishable downstream?
Answers

1. By one. Rounds are counted per Content entry, and parallel responses arrive in a single entry. 2. Zero — transfer_to_agent is not in that branch's tool set, so it is not counted. Counting it would skip the specialist's first tool call silently. 3. Because that is what GoogleLlm does, and the adapter turns it into an authoritative message.complete; a fake that behaved differently would invalidate every test written against it. 4. The call id is prefixed with the model name, which differs per agent.
